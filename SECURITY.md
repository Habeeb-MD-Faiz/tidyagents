# Security

Do not post credentials, private paths, real configurations, histories, or inventories in issues.

For a suspected exposure or destructive behavior, stop the affected run and keep its artifacts private. Report through the repository's private vulnerability reporting channel if enabled. If none exists, open an issue asking for a private contact without including sensitive details. Do not send evidence until a maintainer confirms a private route.

Use a synthetic reproduction. Include kit version, OS, Node version, operation, expected result, and observed result. State whether any original was changed.

No security boundary is promised by instruction files, filename screening, same-user hooks, or an environment wrapper. Discovery can identify suspicious names but cannot prove arbitrary files contain no secrets. Clear content with the owner before hashing, copying, or reviewing it.

The shipped hook is optional and Claude-specific. It asks for every shell command and unfamiliar tool. It is not a shell parser. A missing hook, bypass mode, process failure, alternate tool, or owner approval can defeat it. Put mandatory secrets isolation outside the agent's writable environment.

Backups preserve ordinary file bytes. They do not certify ACLs, alternate streams, extended attributes, cloud hydration, or application consistency. Keep those systems outside generic apply.
