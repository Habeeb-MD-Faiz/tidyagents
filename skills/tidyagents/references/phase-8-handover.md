# Phase 8: hand over

Write STATE, restore guide, closeout, and the change log. Keep a pointer to the reviewed plan and its fingerprint, manifests, current doctor report, and fresh-session evidence for live activation. A phase-5 file-only closeout names that track and marks live behavior untested.

Use bootstrap.ps1 or bootstrap.sh with a newly reviewed plan to recreate adapters on a prepared machine. Paths, versions, account boundaries, and preconditions must be checked again. The bootstrap delegates to apply; it does not install tools, restore auth, change PATH, or register schedules.

For file rollback, use the verified backup as a source in a new copy plan. Pin the current successor as expected_target. This retains the successor before restoring the old bytes. Never overwrite a changed file merely because it is called a backup.

For a newly created link, stop its consumer and have the owner review a single-link relocation into a new sibling archive path. Verify the link object and target first. Move the link object only; never recurse, follow it, or delete its target. Generic apply deliberately refuses conflicting link changes.

Have the owner perform a small restore rehearsal. Confirm instructions, intended identity, and native resume afterward. Keep secrets owner-handled.

List deferred work with reason, owner, trigger, and first safe step. Examples include untested tools, external isolation, parked skills, platform adapters, or a future service gateway. Do not report a design as deployed.

Choose a doctor cadence with the owner. Do not create a schedule without approval. Check again after tool updates, profile changes, plugin installation, or drift.

Gate: the owner can find the records, run doctor, explain the enforcement gaps, and restore a tested adapter.
