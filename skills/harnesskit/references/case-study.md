# Case study

Evidence status: the supplied records describe a real reconciliation that began during a broader data migration. This is an anonymized account, not an independently reproduced benchmark. The kit generalizes the method, not the owner's configuration.

The final tracked repository contained 491 files: 53 core files and 438 third-party skill files. Its documentation set had 32 files. Its history showed 32 commits over seven days. These counts describe that snapshot; they are not targets for a healthy harness.

The days below are narrative stages. Earlier discovery preceded the seven-day repository history, and stages overlapped.

| Stage | Observation | Decision or lesson |
|---|---|---|
| Day 1 | A data audit revealed agent state, multiple profiles, histories, launchers, and shared links | Treat the harness as its own workstream and preserve histories |
| Day 2 | Fresh scans contradicted old reports; owner context changed inferred causes | Recheck live state and ask self-contained questions |
| Day 3 | Separate copies of instructions and account rules drifted | Put portable intent in one repository and keep scope/account rules distinct |
| Day 4 | Tool-specific discovery required imports, copies, and links | Verify actual loading instead of assuming file presence |
| Day 5 | Guards missed path variants and hooks did not cover every tool path | Use fixtures, native controls, and explicit enforcement gaps |
| Day 6 | Additional profiles, shared capabilities, and scheduled work exposed identity and authorization risks | Check actual identity and separate approval from execution |
| Day 7 | Usage analysis found duplicate counts, missing archives, and uncertain attribution | State denominators, retain valued features, and hand over with doctor and restore checks |

Verified in the supplied evidence: canonical instructions, profile adapters, guard hardening, restore work, and repeated audit corrections were implemented. Some tests were local fixtures or reports rather than full runtime acceptance.

Needs checking in the original evidence: uniform cross-provider behavior, every account's effective settings, broad runtime history compatibility, and complete external secrets isolation. Cursor parity was not demonstrated. The kit does not inherit those claims.

The most useful outcome was a repeatable decision process: understand, discover, ask, decide, stage, adapt, guard, verify, and hand over. A future gateway and agent coordination layer remained separate design work; no such service is shipped here.
